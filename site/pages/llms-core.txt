Independent project · Open alpha · No customers yet. For biotechnology, microbiology, chemistry and materials science labs, and the people who build their AI agents and pipelines.

Works today:
- iqc.mjs {{version}}: one file; Node.js 22 or later on Windows, macOS or Linux; no dependencies; it never uses the network.
- iqc watch, iqc seal: seal every file in a folder by its bytes, from any instrument software (SHA-256, size, time), each record signed (ECDSA P-256) and linked to the one before, in <folder>/ImmutableQC/ledger.jsonl.
- iqc record, iqc trace, iqc review: record an AI agent's step (what it read, wrote and did) in the agent's own ledger, trace a file back to sealed files, sign off steps.
- iqc audit: check every ledger and every file under a lab folder: {{exitLine}}.
- iqc mcp: the same for AI agents over MCP on standard input and output. Protocol versions {{protocols}}.
- The app, https://immutableqc.com/app/: audits a lab folder in the browser with nothing uploaded, traces agent outputs back through recorded steps to sealed files, sends untraced inputs to review, and signs off steps in its review mode.

Upcoming: an npm package; a Windows installer and service; values read from inside files; per-person keys and signatures; Merkle batches; sealing inside the vendor's software; post-quantum signatures.

Try it in one command (Linux; it runs only if the SHA-256 matches):
curl -fsSO https://immutableqc.com/download/iqc.mjs && echo "{{dlSha}}  iqc.mjs" | sha256sum -c - && node iqc.mjs help
macOS: shasum -a 256 -c. Windows: certutil -hashfile iqc.mjs SHA256, then compare. If they differ, do not run it.

Connect it from any MCP client that starts local servers over standard input and output:
{{configJSON}}
- --root: the folder the agent works in; every path a tool takes must be inside it.
- --search (repeatable): where the instruments' ledgers are. Give the lab folder, or a file sealed outside the root reads as untraced.

The four tools (each result says which folders it searched):
- check_inputs {paths}: per file, measured (a ledger sealed these exact bytes; its key id), derived (a recorded step wrote them) or untraced, and whether a sealed file changed after it was sealed. Only files a lab station sealed read as measured. Never run iqc seal or iqc watch on files yourself. Reads only.
- record_step {action, inputs, outputs, input_refs?}: appends one signed record of a step (files by SHA-256 and size); the tool cannot remove it; a person reviews it. Recorded even when an input is untraced, with a warning.
- trace {path}: a file's tree back to sealed files, and tracesToMeasured.
- audit_summary {strict?}: pass, review or fail for every ledger under the search folders. Every tool but record_step reads only.

The loop: check_inputs before you use lab files; tell the person about an untraced or changed input before you rely on it; record_step once per step, naming every file you read and wrote (from outside the root: copy it in, or use input_refs <sha256>:<bytes>:<label>); trace or audit_summary before you report. A person signs off steps (iqc review, or the app's review mode); MCP has no review tool.

Limits:
- A pass does not show that a file was right when it was written, or a change made inside the settle window (10 s by default) before it was sealed.
- Whoever holds a ledger's key could rewrite it, and a ledger cut short (its last records deleted) needs no key: both show only against a head pinned earlier (iqc head, then iqc audit --expect-head, or --pin-file); audit_summary checks none.
- Measured means some ledger sealed those bytes, whatever its key: anyone, an agent included, can run iqc seal under any station name. Compare measured.keyId with the lab's station key ids (iqc status prints them); a built-in check is upcoming.
- A step records only the files it names. A trace follows the steps as the agent recorded them: a step can name inputs it did not use, or outputs it did not compute from them. A person's review checks that.
- A key identifies a computer or a browser, not a person; per-person signatures are upcoming.
- Values inside files are not read; reading them is upcoming.
