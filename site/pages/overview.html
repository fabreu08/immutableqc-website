2Why: one wrong value snowballs

{{whyNow}}

A wrong value usually comes from the software that already sits between the instrument and the record:

  • a script that “fixed” the units
  • a sync conflict between two copies
  • a crash halfway through a write
  • a backup restored from last week
  • a migration that rounded values
  • an outage that dropped a batch
  • a model that filled in a blank

One wrong value does not stay put: it feeds an analysis, the analysis feeds a model, and the model picks the next experiment. A sealed record shows whether a value is still what was captured; upcoming, derived records that cite the measurements they came from would make a corrected value’s reach computable: every analysis, model and decision that used it.

5Today, upcoming and not claimed

  • Alpha console · demo in your browserRuns on a synthetic lab, only in your browser. Each record gets a SHA-256 fingerprint, a link to the record before it (the first record links to a fixed start value of 64 zeros), and a signature from a demo key made in your browser. Corrections are new records with a reason, and every check is recomputed after each change. Its anchor is simulated, with no network call.
  • These pagesThe same construction on one synthetic sequence, signed with a demo key at build. Your browser recomputes every check.
  • Alpha app · not publicImports HPLC CSV exports. Each peak area becomes a record of instrument, measurement type, value, unit and capture time, fingerprinted, linked and signed by one server key. The capture time is an injection time typed at import, or the server’s clock if none is given.
  • UpcomingSealing at capture (SiLA 2 and OPC UA LADS adapters), measured and derived records, lineage and recall, Merkle batches with salted leaves and inclusion checks, anchoring batch fingerprints on a public test network, an encrypted archive on Filecoin, post-quantum signatures, a shared registry, reviewer sign-off, server-side verification in the app, per-analyst signatures, sample and method metadata in the seal, privacy on public networks and agentic workflows. Every anchor on this site and in the console is simulated.
  • Not claimedNo customers, no capture at the instrument or orchestrator, no electronic signatures and no validation. Nothing on this site or in the console writes to a public network.

BasisThe same five fields and link rule in the alpha app’s HPLC import and on these pages; in the app, the instrument field is its internal instrument number. The console documents its own payload in its Method panel.

6Where it fits

In an automated lab, software already sits between the instrument and the record: the scheduler or orchestrator, the device drivers and the data pipeline that feeds models and agents; sealing each result there, as it is produced, over SiLA 2 or OPC UA LADS, is upcoming. Today, Immutable QC sits beside the export: the alpha app fingerprints, links and signs each peak area imported from an HPLC CSV with one server key, and checking them in the app is upcoming. On these pages and in the console the record history is tamper-evident, so a later change to a sealed value fails its checks. Changes made before capture are not covered.

6.1When your process moves into GMP

Your instrument, CDS, LIMS and QA review stay as they are. In the alpha, Immutable QC sits beside the CDS export; nothing is sent back to the CDS or LIMS, and the sealed history is what a reviewer or an auditor would check.

8Agentic workflows Upcoming

An agent would run the same four checks as Check a record before it uses a result. Passing them says a result has not changed since it was sealed; it does not say the result was right when it was captured, or that it was ever measured.

Measured and derived records, upcoming: only a record sealed at capture, by the instrument’s or orchestrator’s key, would count as measured. Anything an agent, a script or an analysis produces would be a derived record, under a different signer, citing the fingerprints of the sealed records it came from. So a number an agent gives either traces back to a measurement or it does not, and one that does not would be flagged before use.

Check a record shows one record as an agent would receive it. There is no API yet.
