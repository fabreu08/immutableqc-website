2Why: one wrong value snowballs

{{whyNow}}

A wrong value usually comes from ordinary software and operations:

  • a script that “fixed” the units
  • a sync conflict between two copies
  • a crash halfway through a write
  • a backup restored from last week
  • a migration that rounded values
  • an outage that dropped a batch
  • a model that filled in a blank

One wrong value feeds an analysis, a model and the next experiment: a concentration a script wrote in mg/mL where the pipeline expects µg/mL can end up in a dose-response fit, a training set and tomorrow’s plates. Today a seal shows a value changed after it was sealed; the upcoming items in section 5 would catch more.

Deliberate changesA value changed on purpose by someone without the signing key fails the same checks. A rewrite with the key, or a deletion with the rest relinked (which needs no key), passes each record’s checks; question 5.7 on the About page says what would show it.

  • Agent · iqc.mjsSeals every file in a folder as the instrument software writes it, records the steps AI agents take on files and serves the same to AI agents over MCP; a person signs off steps with iqc review. One file for Node.js 22.

  • Alpha app · not publicImports HPLC CSV exports and seals each peak area (instrument, measurement type, value, unit, capture time) with one server key. The capture time is an injection time typed at import, or the server’s clock.

6Where it fits

In an automated lab, the scheduler or orchestrator, the device drivers and the data pipeline sit between the instrument and the record. Sealing each result in the orchestrator or driver, as the instrument produces it, over SiLA 2 or OPC UA LADS, is upcoming.

Today, Immutable QC sits beside an HPLC CSV export: the alpha app fingerprints, links and signs each imported peak area with one server key. On these pages the record history is tamper-evident. Today a change made before import is not covered; with sealing at capture, only a change made before capture would be.

6.1When your process moves into GMP

Your instrument, CDS, LIMS and QA review stay as they are. In the alpha, Immutable QC sits beside the CDS export and sends nothing back; a reviewer or an auditor would check the sealed history.

8Agentic workflows

Today the agent records the steps AI agents take on files: what each step read and wrote, by SHA-256, and what it did, in the agent’s own signed ledger, through iqc record or the agent’s MCP server, which AI agents call over standard input and output. Before an agent uses a file, check_inputs says whether its bytes are a sealed measurement, the output of a recorded step, or neither; an audit traces every agent output back to sealed measurements, and a person signs off each step.

A pass says a file has not changed since sealing, not that it was right, or that it was ever measured. That works on whole files. With measured and derived records, upcoming, only a record sealed at capture, by the instrument’s or orchestrator’s key, would count as measured, so a number either traces back to a measurement or it does not. A derived number that cites real measurements but was computed or copied wrongly would still pass; a checker would re-run the analysis from its cited inputs where it is deterministic.

Check a record shows one record of this construction as an agent would receive it. A reviewer’s key identifies a computer or a browser, not a person; per-analyst signatures are upcoming.
