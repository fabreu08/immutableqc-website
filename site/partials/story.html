3How a result becomes a sealed record

One record from the demo sequence, record {{sn}} of {{seq}}, in seven steps from the instrument run to its place in the record history. Every value shown is computed from the signed demo data when the site is built.

  1. 3.1Captured

    Injection {{c_inj}} on {{instrument}}. The chromatography data system (CDS) integrates the peak at {{c_rt}} min, and its area, {{f_value}} counts, becomes the value of record {{sn}}, with four more fields: the instrument, the measurement type, the unit and the capture time.

    {{storyFig1}}

  2. 3.2Fingerprinted

    The five fields are joined by a vertical bar into one line of {{pbytes}} bytes: {{payloadW}}. SHA-256 turns that line into a 64-character fingerprint, r{{sn}}. One changed character gives a completely different fingerprint.

    {{storyFig2}}

  3. 3.3Signed

    The fingerprint is signed with the demo key (ECDSA P-256, key id {{keyIdShort}}…), and anyone with the public key can check that the signature covers this fingerprint and no other.

    {{demoSig1}}

    {{storyFig3}}

  4. 3.4Linked

    Record {{sn}} also stores the link of record {{sp}}, h{{sp}}. Its own link is h{{sn}} = SHA-256(h{{sp}} + r{{sn}} + “{{sn}}”), and record {{snext}} carries h{{sn}} forward as its previous link. So every record is tied to the one before it, back to the fixed start value of 64 zeros.

    {{storyFig4}}

  5. 3.5A change shows

    Suppose the peak area is changed after sealing, from {{f_value}} to {{st_value}}: the recomputed fingerprint differs from the stored r{{sn}}, the signature fails and the link into record {{snext}} breaks, while records {{snext}} and {{N}} still pass their own checks. So {{st_rule}}. Replayed from 64 zeros, the head (the newest record’s link) no longer matches the anchored fingerprint, which is simulated here.

    {{st_vals5}}
    {{storyFig5}}

  6. 3.6A correction is appended

    Made the right way, the same change is a correction: record {{sn}} stays as sealed, and a new record {{st_n9}} holds the new value, {{st_value}}, with its own fingerprint, a link from record {{N}} and a signature. Its reason (“{{st_reason}}”) and “corrects #{{sn}}” sit beside the seal, not inside it; all {{st_n9}} records pass, and the new head, h{{st_n9}}, is not yet anchored.

    Record {{st_n9}} is signed with a one-time demo key (key id {{st_key9}}…), made at build and then discarded, as Check a record signs a correction with a one-time demo key made in your browser; the demo key that signed records 1 to {{N}} was discarded too, so it cannot sign anything new.

    {{st_vals6}}
    {{storyFig6}}

  7. 3.7What comes next Upcoming

    Upcoming: the head of a batch, here h{{N}}, written to a public network. Only that fingerprint would go on the network, never the values. Upcoming too: an AI agent that checks fingerprint, signature, link and anchor before it uses a result.
